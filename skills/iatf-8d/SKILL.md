# 8D 问题解决技能

## 何时使用

满足以下任一条件时加载：

- 消息含"投诉 / 客诉 / 退货 / 失效 / 批量不良 / 产线异常"；
- 客户或售后反馈产品功能中断、性能下降；
- 内部审核发现重复性不合格。

不适用：单件偶发的外观瑕疵、纯文档问题。

## 前置检查

| 检查 | 不满足时 |
| --- | --- |
| 已识别产品型号与批次 | 先问一个具体问题 |
| 已识别问题现象 | 先问一个具体问题 |
| 已判断是否涉及安全件 | 涉及则立即升级为高风险 |

## 执行步骤

### D1 成立小组（24h）

1. 从项目团队成员表中选取：质量、设计、工艺、生产、供应商（如需）。
2. 指定组长，必须是能调动跨职能资源的人。
3. 在工单中记录名单与联系方式。

**输出**：D1 段落填写完整。

### D2 描述问题（48h）

1. 用 5W2H 结构化描述。
2. 必须包含：数量、比例、时间、地点、现象。
3. 要求证据：日志、照片、故障件。

**判据**：读者不看现场也能理解问题。

### D3 临时措施（72h）

1. 覆盖三个范围：客户端、库存、在制。
2. 每条措施必须有责任人、完成日期、验证方式。
3. 验证临时措施是否真正阻断了流出。

**禁止**：把"加强检验"当作唯一措施而不说明检验方法。

### D4 根因分析（7d）

1. 先做失效分析（FA），拿到物证。
2. 用 5Why 追到"为什么系统允许它发生"。
3. 区分**根本原因**与**流出原因**，两者都要有。
4. 鱼骨图覆盖人机料法环测六类，逐项排除。

**判据**：根因可复现；移除根因后问题不再发生。

### D5 永久措施（14d）

1. 每条措施标注类型：纠正 / 探测 / 预防。
2. 涉及设计或过程变更的，必须关联 ECN。
3. 涉及 FMEA/控制计划的，必须同步更新。

**禁止**：只做探测措施而不做预防措施。

### D6 验证（21d）

1. 验证方法必须可量化。
2. 样本量要能支撑结论。
3. 必须有客户端或长期跟踪数据。

**判据**：验证数据能证明措施有效，而非"没有再次发生"。

### D7 预防再发（28d）

1. 更新 DFMEA / PFMEA / 控制计划 / 作业指导书。
2. 登记经验教训库。
3. 横向展开到同类产品。

**判据**：同类问题在其他项目中被主动排查。

### D8 结案（30d）

1. 汇总全过程。
2. 客户确认。
3. 记录经验教训。

## 输出要求

| 项 | 要求 |
| --- | --- |
| 模板 | `templates/15-8D报告.md` |
| 路径 | `docs/S5-量产/8D/8D-<项目>-<流水>-<简述>.md` |
| 必填 | D1–D8 全部段落 |
| 证据 | 每阶段至少一个证据文件 |
| 时限 | 每阶段记录实际完成时间 |

## 常见错误

| 错误 | 后果 | 纠正 |
| --- | --- | --- |
| 根因写成"操作不当" | 无法预防 | 继续追问为什么系统允许 |
| 临时措施只有全检 | 流出未阻断 | 增加源头隔离 |
| 验证只看"没再发生" | 结论不成立 | 要求量化数据 |
| 不做横向展开 | 同类问题复发 | 强制 D7 检查 |
| 时限造假 | 审计风险 | 记录真实时间 |

## 与其他技能的关系

- 需要变更时：加载 `ecn`；
- 需要更新 FMEA：加载 `iatf-dfmea` 或 `iatf-pfmea`；
- 需要更新控制计划：加载 `iatf-control-plan`；
- 需要提交仓库：加载 `repo-ops`。
