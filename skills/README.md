# 领域技能

技能是"按需加载的领域知识"。系统提示词只放通用规则，具体方法论放在技能里，由执行器在需要时加载。

## 1. 技能清单

| 技能 | 触发 | 关键内容 |
| --- | --- | --- |
| `iatf-8d` | 质量问题 | D1–D8、5Why、鱼骨图、时限 |
| `iatf-dfmea` | 设计 FMEA | 七步法、S/O/D 准则、AP 判定 |
| `iatf-pfmea` | 过程 FMEA | 过程步骤、失效库、控制措施 |
| `iatf-control-plan` | 控制计划 | 特性、方法、频次、反应计划 |
| `iatf-msa` | 测量系统分析 | GRR 设计、计算、判定 |
| `iatf-spc` | 过程能力 | Cpk/Ppk、控制图选择 |
| `iatf-ppap` | PPAP | 18 项要素、提交等级、PSW |
| `iatf-apqp` | 项目策划 | 五阶段、交付物、阶段门 |
| `ecn` | 变更管理 | 影响分析、分级、审批 |
| `repo-ops` | 仓库操作 | 分支、提交、PR、校验 |
| `asset-taxonomy` | 产物归属 | 文档/代码/硬件分类与命名 |
| `feishu-reply` | 回写消息 | 格式、长度、静默规则 |

## 2. 技能结构

```
skills/<name>/
├── SKILL.md          # 触发条件、步骤、输出要求（必需）
├── references/       # 标准条款、评分表、检查清单
└── templates/        # 该技能使用的模板（可引用全局模板）
```

`SKILL.md` 的 front-matter：

```yaml
---
name: <技能名>
description: <一句话说明何时使用>
version: 1.0
appliesTo: [<任务类型>]
---
```

## 3. 编写原则

| 原则 | 说明 |
| --- | --- |
| 可判定 | 写明"什么条件下使用"，不写"视情况" |
| 可执行 | 步骤是动作，不是概念解释 |
| 可校验 | 输出有明确的检查项 |
| 不重复 | 通用规则放系统提示词，技能只放领域特化内容 |
| 有出处 | 引用标准条款号，便于审计 |

## 4. 技能与模板的关系

- 技能负责"怎么做"；
- 模板负责"长什么样"；
- 校验器负责"合不合格"。

三者分离，避免把方法论写死在模板里。
