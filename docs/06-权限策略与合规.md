# 06 权限策略与合规

## 1. 授权模型总览

三层授权，缺一不可：

```
身份（谁） ──▶ 范围（能做什么） ──▶ 时机（现在能不能做）
   Gate            Mandate              Stage Gate
```

任何一次写操作都必须同时满足三层，否则拒绝并记录原因。

## 4. 授权（Mandate）结构

```yaml
mandate:
  id: MND-2026-0031
  ticket: TKT-2026-0031
  policyVersion: pv-2026-11-21-a
  grantedBy: ou_xxx3
  grantedAt: 2026-11-21T09:12:00+08:00
  strength: explicit
  project: PCU24
  stageScope: [S2, S3]
  gateTarget: G2
  repoScope:
    - firmware/app/motor/
    - docs/S2-产品设计/
    - hardware/bom/
  actionScope:
    - write_docs
    - write_code
    - update_bom
    - open_pr
  denied:
    - merge_pr
    - push_main
    - release_tag
  matchedRules: [rule-design-change]
```

**不可变**：创建后任何字段不得修改。扩大范围必须新开工单。

**撤回**：只有人能撤回（飞书指令 `@机器人 停止 TKT-xxx` 或面板操作）。

**重新校验**：工单恢复前，按当前策略重新校验；不通过则授权失效，工单保持关闭。

## 5. 策略版本

### 5.1 版本构成

策略版本 = 规则集 + 接受模式 + 各来源的角色与准入表 + 阶段门签署人配置。

每次修改生成新版本，记录：

- 版本号
- 修改人
- 修改内容
- 生效时间

### 5.2 变更影响

| 变更类型 | 对运行中工单的影响 |
| --- | --- |
| 收紧准入 | 不撤销已有授权，但恢复时重新校验 |
| 扩大准入 | 立即对新消息生效 |
| 修改规则 | 丢弃运行中的 Eval，重新排队 |
| 修改阶段门签署人 | 影响后续签署，不影响已签署 |

### 5.3 通知

受影响工单收到"策略变更通知"，说明：

- 哪条规则变了；
- 是否仍被覆盖；
- 是否需要重新授权。

## 6. 审计与记录保存

### 6.1 必须留存的记录

| 记录 | 内容 | 保存期 |
| --- | --- | --- |
| 工单 | 触发、决策、授权、执行、结果 | 15 年 |
| 文档版本 | 每次修订的完整快照 | 15 年 |
| 阶段门记录 | 检查项、签署人、时间、结论 | 15 年 |
| 变更记录 | ECR/ECN、影响分析、批准 | 15 年 |
| 8D | 全过程与验证证据 | 15 年 |
| 执行日志 | 执行器动作、命令、输出 | 3 年 |
| 审计日志 | 谁在何时做了什么 | 15 年 |

> 15 年为汽车行业常见要求，实际以企业体系文件与客户特殊要求为准。

### 6.2 审计可查项

任意一条记录应能回答：

1. 这件事是谁提出的？
2. 依据哪版策略、哪条规则被接受？
3. 授权范围是什么？
4. 执行器做了什么、改了哪些文件？
5. 谁审核、谁签署、何时生效？
6. 关联的需求、文档、测试、变更是什么？

### 6.3 防篡改

- 所有记录写入后不可修改，只能追加；
- 关键记录（签署、发布）计算哈希并链式存储；
- 定期导出归档到只读存储。

## 7. 数据安全

### 7.1 密级

| 密级 | 范围 | 措施 |
| --- | --- | --- |
| public | 可外发 | 无限制 |
| internal | 内部 | 仓库权限控制 |
| confidential | 项目组 | 细粒度权限 + 水印 |
| restricted | 核心 IP | 加密存储 + 审批访问 |

### 7.2 敏感信息

系统必须防止：

- BOM 与原理图外泄；
- 客户信息外泄；
- 密钥、证书进入仓库；
- 模型调用时上传敏感文件。

**措施**：

- 提交前密钥扫描；
- 敏感文件默认不进入模型上下文；
- 外部模型调用需脱敏；
- 导出需审批并留痕。

### 7.3 凭据管理

| 凭据 | 存放 | 使用 |
| --- | --- | --- |
| 飞书 app secret | 独立配置目录 | 机器人身份 |
| Git 凭据 | 专用账号配置目录 | agent 账号 |
| 模型密钥 | 环境变量/密钥管理 | 运行时注入 |

禁止：明文写入仓库、写入日志、在聊天中传输。

## 8. 合规红线

以下行为系统必须拒绝，且不可通过提示词绕过：

1. 非白名单人员发起工单；
2. 越过阶段门执行下一阶段任务；
3. 修改授权范围外的文件；
4. 直接推送到受保护分支；
5. 代替人签署阶段门；
6. 删除已发布文档或记录；
7. 将受限资料发送到外部；
8. 关闭审计日志。

## 9. 与 IATF 16949 条款的对应

| 条款主题 | 本方案对应 |
| --- | --- |
| 文件化信息控制 | 文档分类、版本、审批、归档 |
| 记录保存 | 15 年留存、防篡改 |
| 变更控制 | ECN 流程、影响分析、重新验证 |
| 不合格品控制 | 8D、临时措施、追溯 |
| 监视与测量 | MSA、SPC、过程能力 |
| 内部审核 | 审计日志、可查项 |
| 管理评审 | 面板度量、阶段门统计 |
| 供应商管理 | SQE 角色、来料问题流程 |

## 10. 权限变更流程

```
提出 → 影响评估 → 信息安全评审 → 批准 → 发布新策略版本 → 通知受影响工单
```

**紧急变更**：允许临时提权，但必须：

- 记录原因与批准人；
- 设置自动过期（默认 24 小时）；
- 到期自动回滚；
- 事后审计。
